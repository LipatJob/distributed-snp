### 1. Throughput Comparison (Steps per Second)

This is the most direct performance metric. This chart compares how many simulation steps each implementation can process per second.

- **Insight:** It highlights the raw speed difference between CPU, Single-GPU (CUDA), and Distributed (MPI) approaches.
- **Separation:** I have separated the charts by **System Size (256 vs 2048)** because the scale of throughput differs significantly between small and large workloads.

### 2. Communication Overhead Analysis (MPI Only)

The `data.json` contains specific fields for MPI communication (`MPI_Comm_ms`). This visualization is crucial for understanding distributed bottlenecks.

- **Visual:** A stacked bar chart showing **Computation Time** vs. **Communication Time**.
- **Insight:** This reveals if your distributed implementations (Linear, Louvain, RedBlue) are "compute-bound" (good) or "bandwidth-bound" (spending too much time talking between nodes).

### 3. Scaling Stability (Small vs. Large Workloads)

This visualization compares how well each implementation maintains its performance as the system size grows from 256 to 2048 neurons.

- **Visual:** A slope chart or paired bar chart showing the % drop in throughput when moving to the larger dataset.
- **Insight:** Helps identify which algorithm scales best. For example, `SparseCudaSnp` might handle memory better but suffer in raw speed, while `CudaSnp` might be fast but drop off quickly as data grows.

### 4. Pattern Sensitivity

Does the input data organization (Sorted, Reverse, Random) affect performance?

- **Visual:** A heatmap or grouped bar chart.
- **Insight:** Some partitioning algorithms (like Linear or RedBlue) might be sensitive to how neurons are ordered. If `Random` is significantly slower than `Sorted`, your partitioning strategy relies heavily on data locality.
